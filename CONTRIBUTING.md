# Contribuir para o Atina II

## Processo
1. Crie uma branch para a sua alteração (`feature/nome` ou `fix/nome`).
2. Faça alterações focadas e com mensagens de commit claras.
3. Execute testes e verificações aplicáveis antes de abrir um pull request.
4. Descreva no PR o objetivo, alterações, validação e eventuais riscos.

## Commits
Preferir mensagens curtas e descritivas, por exemplo:
- `docs: atualizar roadmap`
- `feat: adicionar funcionalidade X`
- `fix: corrigir comportamento Y`

## Qualidade
- Evite introduzir dependências sem necessidade.
- Atualize documentação quando o comportamento ou configuração mudar.
- Nunca inclua credenciais, dados pessoais ou ficheiros locais sensíveis.
